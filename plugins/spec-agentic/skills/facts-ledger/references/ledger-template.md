# Ledger template

Copy into the project as a single canonical file (for example `docs/facts-ledger.md`) and declare
it canonical in the project instructions. One file. If there are two, neither is canonical.

````md
---
title: Facts Ledger — <project>
type: canonical-register
status: live
updated: <date>
maintained_by: ["/fact-intake", "/fact-check"]
---

# Facts Ledger — <project>

> The single canonical register of facts about the counterparty's system. Load it **before** any
> design, conceptualisation or recommendation. This is not analysis; analysis lives elsewhere and
> is never citable as fact.

## States

- **LOCKED** — confirmed by an allowlisted counterparty source. Immutable in every design.
- **WORKING** — our own proposed direction, not confirmed. Degree of freedom. Never presented as
  fact. Promotes via the intake ritual.
- **OPEN** — explicitly unconfirmed in the source. A question, never a premise.
- **D__** — our own engineering decision. Binding on the build, never a counterparty fact,
  never promoted to LOCKED.

## Valid sources (the only paths citable as fact)

- `<path>/**` — <what it is>, EXCEPT `<path>/analysis/**` (generated by us)
- `discovery/NN-*.md` — statements made by the counterparty in recorded sessions
- `meetings/**` — dated meeting records
- `<vendor>-api-map/**` — citable ONLY as vendor capability, never as this instance's
  configuration; label `[vendor-capability — not their config]`

**Never citable as fact:** our own analysis, the WORKING/OPEN rows below, model knowledge, the
open web, assumptions made earlier in a conversation.
````

## Conventions worth enforcing from day one

- **IDs are permanent.** Monotonic per family, never reused, never renumbered. A retired row is
  struck through and kept.
- **Sub-IDs for clauses.** `L41·c` addresses clause c, so a document can depend on the exact part
  it needs and a correction to clause a does not invalidate every citation.
- **Verbatim in the original language.** Translating a quote destroys the ability to verify it.
  Put the translation in the statement column if you need one; keep the quote untouched.
- **The "artefacts affected" column is not documentation.** It is the work list for the day a fact
  changes. Fill it honestly or the correction pass will miss files.
- **One line per fact.** A row that carries three facts cannot be promoted, corrected or cited
  independently. Split it.
